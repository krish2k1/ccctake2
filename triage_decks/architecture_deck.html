03 / COMPONENT MAP

Four components, each independently deployable

C1 · SERVICE IDENTIFIER

What to engage

Hybrid decision engine. Receives a claim snapshot. Emits services_needed[ ] with type (DET/PROB/TIME/HUMAN), confidence, when, why (feature attribution).

  • Tech: rules engine + multi-label classifier + survival/timing model
  • Cadence: synchronous on snapshot event
  • State: stateless inference; model artifacts pulled from registry
  • Output: ServiceRecommendations event
C2 · VENDOR POOL + SCORECARD

Who can do it; who's best at it

Vendor master, eligibility evaluator, per-claim composite scorer. Receives service + claim context. Emits ranked candidates with factor breakdown.

  • Tech: RDB for master, feature store for scores, vector cache for specialty-fit
  • Cadence: sync for inference; async weekly score refresh
  • State: heavy — vendor master, scores, capacity
  • Output: VendorRanking event per service
C3 · RECOMMENDATION COMPOSER

One narrative for the adjuster

Composes ServiceRecommendations × VendorRanking × audit metadata into the adjuster-facing recommendation. Persists immutably with lineage to predecessor.

  • Tech: stateless orchestrator + append-only ledger
  • Cadence: synchronous
  • State: only via the ledger
  • Output: Recommendation event + UX payload
C4 · ATTRIBUTION + LEARNING LOOP

How we know it works

Propensity-matched outcome attribution, vendor scorer refresh, classifier retrain, drift monitor, override-pattern miner.

  • Tech: batch pipeline + streaming drift monitor + model registry
  • Cadence: weekly score · quarterly retrain · monthly threshold review · monthly override review
  • State: warehouse + model registry
  • Output: ScoreRefresh · ModelVersion events; finance attribution report

Per-claim filter additionally enforced at runtime: jurisdiction match · conflict-of-interest exclusion · claim-specific exclusion list · capacity below 85%.

// EligibilityEvaluator — pure function
function isEligible(v: Vendor, s: ServiceId, c: Claim): Verdict {

  // Gate 1-8: vendor-level
  if (v.eligibility.licensure.status !== "current") return { ok: false, fail: "G1" }
  if (!hasMinLimit(v.eligibility.eo_insurance)) return { ok: false, fail: "G2" }
  if (v.eligibility.baa.status !== "executed") return { ok: false, fail: "G3" }
  if (!hasAttestation(v, s)) return { ok: false, fail: "G4" }
  if (v.eligibility.regulatory_actions.length > 0) return { ok: false, fail: "G5" }
  if (v.eligibility.soc2.type !== "II") return { ok: false, fail: "G6" }
  if (!hasRateCard(v, s, c.jurisdiction)) return { ok: false, fail: "G7" }
  if (v.eligibility.capacity.current_util > 0.85) return { ok: false, fail: "G8" }

  // Per-claim filter
  if (!v.jurisdictions.includes(c.jurisdiction)) return { ok: false, fail: "jurisdiction" }
  if (hasConflictOfInterest(v, c)) return { ok: false, fail: "COI" }
  if (c.exclusion_list.includes(v.vendor_id)) return { ok: false, fail: "excluded" }
  if (!v.services_offered.includes(s)) return { ok: false, fail: "service" }

  return { ok: true }
}
07 / VENDOR SCORER

Per-claim composite. Causal correction. Time decay. Governance overlay.

// CompositeScore(vendor, claim, service)

function scoreFor(v: Vendor, c: Claim, s: ServiceId): Score {

  // 1. base factor pulls from the vendor's cached score
  //    per (service, jurisdiction). Recomputed weekly.
  const base = v.scores.find(x => x.service_id === s
                              && x.jurisdiction === c.jurisdiction)

  if (!base || base.n_closed < 30) {
    return { rank: "provisional", eligibleFor: "exploration" }
  }

  // 2. specialty fit is computed per-CLAIM, not stored
  const specialty = computeSpecialtyFit(v, c, s)
  //   - body part match
  //   - language match
  //   - geographic distance / coverage
  //   - venue history (defense counsel)

  // 3. weights default; per-family overrides allowed
  const w = weightsFor(s.family)

  return { composite:
    w.outcome * base.outcome      // propensity-adjusted
  + w.cost    * base.cost
  + w.speed   * base.speed
  + w.specfit * specialty
  + w.adjsat  * base.adj_sat
  + w.compl   * base.compliance,

    breakdown: { outcome, cost, speed, specialty, adjsat, compliance },
    n_closed: base.n_closed,
    refreshed_at: base.refreshed_at,
    estimated_cost_band: estimateCost(v, c, s),
    estimated_outcome_band: estimateOutcome(v, c, s)
  }
}

// Outcome correction (offline, weekly refresh)

// Top vendors get easier claims. Without correction
// the score conflates skill with assignment.

function refreshOutcomeScores(window: TimeRange) {

  const closed = closuresIn(window)

  // covariates we control for
  const X = ["severity_at_engagement", "litigation_propensity",
             "ncci_body_part", "jurisdiction", "venue",
             "age_band", "days_from_doi_at_engage"]

  // propensity model: P(vendor_v | X)
  const propensity = fitPropensityModel(closed, X)

  // inverse-probability weighting → unbiased outcome estimate
  for (const v of vendors) {
    for (const svc of v.services_offered) {
      for (const j of v.jurisdictions) {
        const w = ipw(closed, v, svc, j, propensity)
        const raw  = avgOutcome(closed, v, svc, j)
        const adj  = weightedAvg(closed, w, svc, j)

        // time decay: last 6mo 60% · 7-18mo 40% · >18mo drop
        const decayed = applyDecay(adj, [0.6, 0.4, 0])

        writeScore(v, svc, j, decayed)
      }
    }
  }
}

12 / NON-FUNCTIONAL REQUIREMENTS

Latency · idempotency · audit · jurisdiction · adoption

NFR-01 · LATENCY

P50 < 2s · P95 < 5s

From inbound event to persisted Recommendation. Snapshot + identify + rank + governance + persist + emit.

NFR-02 · IDEMPOTENCY

Replay-safe

Same event + same snapshot + same model versions → identical Recommendation. Persistence keyed on deterministic hash to deduplicate.

NFR-03 · IMMUTABILITY

Append-only ledger

Recommendations never mutate. Corrections create successor records linked by predecessor.

NFR-04 · AUDIT

Reproducible at point-in-time

Snapshot, model versions, weights, scores, candidates, action, outcome — all linked, all queryable, all retained per state schedule.

NFR-05 · PHI / HIPAA

Encryption + minimum necessary

At-rest AES-256, in-transit TLS 1.3. Vendor packets redact identifiers; claim_number is opaque to vendor.

NFR-06 · JURISDICTION

Config, not code

Eligibility rules, scoring weights, consumer-notice copy, surveillance approval routing — all data-driven per state.

NFR-07 · OBSERVABILITY

Per-event tracing

Trace ID propagated from inbound event through C1 → C2 → C3 emit → vendor API call. Latency per component.

NFR-08 · DEPLOY

Independently deployable

C1/C2/C3/C4 each deployable behind feature flags. Shadow mode for new classifier versions.

NFR-09 · ADOPTION

≥70% acceptance by end of Phase 2

Measured by AdjusterAccepted ÷ RecommendationIssued. Acceptance ratio is a product KPI, not an individual adjuster KPI.

13 / LEARNING LOOP

Four cadences. Each closes a different feedback gap.

Attribution loop runs in parallel: propensity-matched estimator on the 5% randomized holdout cohort publishes counterfactual savings to finance each quarter. Without this, the whole program's value is unprovable.
